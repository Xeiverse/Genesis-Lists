# ADR 0005: OpenID Connect (OIDC) Authentication

## Status

Accepted

## Context

Self-hosters often already run an IdP (Authentik, Authelia, Keycloak). Immich-style OIDC lets Genesis Lists reuse that identity without rewriting list APIs. ADR 0002 already uses server-side session cookies; OIDC should establish those sessions after a successful IdP login rather than introducing JWTs in the SPA.

There is no admin settings UI. Operators configure the stack with environment variables, the same pattern as `SESSION_SECRET` and `ALLOW_REGISTRATION`.

## Decision

- Support **OpenID Connect Authorization Code** with **PKCE** for a single confidential client.
- Configure via **environment variables** only (`OIDC_*`, plus `PUBLIC_BASE_URL` / `OIDC_REDIRECT_URI`).
- After a successful callback, create a row in `sessions` and set the signed `genesis_session` cookie (unchanged from ADR 0002).
- Bind OIDC `state` to the initiating browser with a signed HTTP-only cookie to mitigate login CSRF.
- Persist external identity in `user_identities` keyed by `(issuer, subject)`.
- **Username merge:** if no identity row exists, match `OIDC_USERNAME_CLAIM` (default `preferred_username`) to `users.username` and link; otherwise auto-register when `OIDC_AUTO_REGISTER=true`. *(Superseded by [ADR 0006](0006-email-login-identifier.md): the merge key is now `OIDC_EMAIL_CLAIM` matched against the unique `users.email`.)*
- Allow nullable `password_hash` for OIDC-only users; store optional `email` from the IdP (not unique in v1). *(Superseded by [ADR 0006](0006-email-login-identifier.md): email is required and unique.)*
- When `OIDC_DISABLE_PASSWORD_LOGIN=true`, reject local password register/login and hide those forms in the UI.
- Fail closed at startup if `OIDC_ENABLED=true` but required settings or discovery are missing.

## Consequences

- List and item routes stay cookie-scoped; no bearer-token rewrite.
- Operators get Immich-like setup docs (Authentik first) without an admin console.
- Logout clears the local session only in v1 (IdP end-session / backchannel logout deferred).
- **Android companion:** start with `?client=android`; successful callback redirects to an HTTPS handoff page (`/api/auth/oidc/android-handoff`) that opens the custom-scheme deep link with a short-lived one-time ticket; the app calls `POST /api/auth/oidc/mobile-exchange` to receive `genesis_session`. The IdP redirect URI stays the web callback — no IdP-side custom scheme. See [ADR 0007](0007-android-companion.md).
- SAML, multiple concurrent IdPs, and an admin UI remain out of scope.
